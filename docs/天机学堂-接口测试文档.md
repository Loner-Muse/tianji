### 3. 测试账号

| 端 | 账号 | 密码 | 说明 |
|---|---|---|---|
| 学生端 | jack | 123 | 用户名登录,或用手机号 13500010003 |
| 管理端 | 13500010002(手机号) | admin | **管理端用手机号登录** |

### 4. 拿 token(所有接口都要带)

```bash
# 学生token
TOKEN=$(curl -s -X POST http://api.tianji.com/as/accounts/login \
  -H "Content-Type: application/json" \
  -d '{"type":1,"username":"jack","password":"123"}' | grep -oE '"data":"[^"]+"' | cut -d'"' -f4)

# 后续请求统一带头:authorization: $TOKEN
```

> ⚠️ token 有效期 1 天,过期重新获取。JWT 是 RSA 签名,不要试图修改内容。

docker exec redis redis-cli -a 123321 DEL "prs:user:coupon:1570595584270774274"
docker exec redis redis-cli -a 123321 DEL "prs:user:coupon:1630121002899881985"
docker exec redis redis-cli -a 123321 HSET "prs:coupon:1570594557152833537" totalNum 100
docker exec redis redis-cli -a 123321 HSET "prs:coupon:1570595584270774274" totalNum 200
docker exec redis redis-cli -a 123321 HSET "prs:coupon:1630121002899881985" totalNum 100

# ---- 签到/积分重置(如需)----

## 三、判读响应状态(测试必备)

| HTTP | body code | 含义 | 处理 |
|---|---|---|---|
| 200 | code:200 | ✅ 成功 | |
| 200 | code:400 | 业务拒绝(参数/库存/限领…) | 看 msg 是否**符合预期** |
| 200 | code:500 | 服务端异常 | **真问题**,查服务日志 |
| 401 | — | 没带token/token过期 | 重新登录 |
| 403 | — | 权限不足(如学员调管理端) | 换管理端token |
| 404 | — | 路径不对(前后端不匹配) | 核对路径 |
| 000/reset | — | 连不上(服务挂/网络) | 查容器、ip_forward |

> ★ 注意:HTTP 状态是 200 但 **body 里 code=400** 很常见(业务失败),**必须看 body**。

## 四、已知业务限制(不是bug,测试时别误判)

| 现象 | 解释 |
|---|---|
| 同一张券第二次领报"领取次数过多" | 每人限领 user_limit 次,正常 |
| 券领完报"库存不足" | 正常 |
| 同一天重复签到被拒 | 正常 |
| 领过的券 available=false | 正常(防重复) |
| 学员token调 `/ls/admin/**` 403 | 正常(需管理端token) |
| 发问题/发回答/签到/领券后再测 | **会产生数据**,用"第一节 5"的重置脚本清理 |

## 五、并发压测(JMeter)

见同目录下压测计划:`天机学堂-自研接口压测.jmx`

**使用步骤**:
1. JMeter → 打开该 jmx
2. 如 token 过期:修改「用户定义变量」里的 `TOKEN`(重新登录获取)
3. 按需调整线程组线程数(默认:查询类100并发×10轮、写入类20并发×5轮)
4. 点绿色启动 → 看「聚合报告」
5. **解读**:先剔除业务错误(400),重点看:
   - 系统错误率(reset/500)
   - 平均响应时间(正常应 <500ms)
   - 吞吐量 TPS

**压测后对账**(以领券为例):
```sql
-- 1.库存
SELECT issue_num,total_num FROM coupon WHERE id=1570594557152833537;
-- 2.实际发放数
SELECT COUNT(*) FROM user_coupon WHERE coupon_id=1570594557152833537;
-- 3.超领检查(期望0行)
SELECT user_id,COUNT(*) c FROM user_coupon
WHERE coupon_id=1570594557152833537 GROUP BY user_id HAVING c>1;
```

## 六、常见故障速查

| 症状 | 排查 |
|---|---|
| 所有接口 502/000 | 服务没起/虚拟机挂了。`docker ps` + `ping 192.168.150.101` |
| 宿主机连不上VM任何端口,但ping通 | **`ip_forward=0`**!`sysctl -w net.ipv4.ip_forward=1` |
| 领券报"活动已结束/领取次数过多" | Redis 缓存与DB脱节,跑"第一节5"的重置 |
| 结算页显示"暂无可用优惠券" | ①无券/券不够门槛 ②promotion服务挂了(trade会降级返回空) |
| 登录返回code:400 | 密码/字段问题(管理端第一框填**手机号**) |
