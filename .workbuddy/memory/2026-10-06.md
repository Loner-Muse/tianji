### 🔴 实测发现并修复的 2 个真 bug

**① `FallbackConfig` 没注册 `PromotionClientFallback` → 服务启动失败**
```
IllegalStateException: No fallbackFactory instance of type class 
com.tianji.api.client.promotion.fallback.PromotionClientFallback found for feign client promotion-service
```
- 根因：`tj-api` 的 `RequestIdRelayConfiguration` 上有 `@EnableFeignClients(basePackages = "com.tianji.api.client")`
  ⇒ **扫描整个 client 包**，连**被调方自己**（promotion 服务依赖 tj-api）也扫到 `PromotionClient`
  ⇒ 配了 `fallbackFactory` 的 Client 必须有一个同类型的 Bean
- `tj-api` 的 `FallbackConfig`（`@Configuration`）就是干这个的，但里面**没有 promotion 那一项**
- **讲义没提这一步** ⇒ 容易漏。**已补** `@Bean PromotionClientFallback`
- ★ **规则**：凡是 `@FeignClient(fallbackFactory = X.class)` 的 Client，X 必须在 `FallbackConfig` 里注册 Bean

**② `userCouponMapper.selectList(lambdaQuery().in(...))` 是错误用法 → 接口 500**
```
MyBatisSystemException: Error evaluating expression 'ew != null and ew.sqlFirst != null'
  Cause: MybatisPlusException: can not use this method for "getSqlFirst"
    at UserCouponServiceImpl.writeOffCoupon(UserCouponServiceImpl.java:273)
```
- 根因：`ServiceImpl.lambdaQuery()` 返回的是**链式 Wrapper**（`LambdaQueryChainWrapper`），
  它**不能当普通 `Wrapper` 参数**传给 `mapper.selectList()`（MP 会对它调 `getSqlFirst()` → 抛异常）
- **修法**：用 MP 自带的 **`listByIds(ids)`**（内部走 `selectBatchIds` → `WHERE id IN (...)`）
- ★ 正确写法：`lambdaQuery().in(...).list()`（**链式到底**）或 `mapper.selectList(new LambdaQueryWrapper<>().in(...))`
- ⚠️ **同时发现 `writeOffCoupon` 被回退成了最初的版本**（`refundCoupon` 还留着我的注释）——
  说明它在 10-05 之后被还原过。**已按批量版重写并补 `usedTime`**

## ★★ 前端报 `AxiosError: Network Error` 的根因：**profile 用错了**（用户截图）

### 根因：`dev` profile 把服务注册成了**虚拟机 IP**
网关日志（错的时候）：
```
加载auth服务地址成功，http://192.168.150.101:8081/jwks     ← 虚拟机 IP！
加载jwk秘钥失败，原因：ConnectException: Connection refused: connect
网关路由异常: Connection refused: getsockopt: /192.168.150.101:8081
```
**项目有两套 profile**（每个服务的 `src/main/resources/bootstrap-{profile}.yml`）：
| profile | 用途 | `nacos.discovery.ip` |
|---|---|---|
| **`dev`** | 所有服务部署在**虚拟机**上 | `192.168.150.101` |
| **`local`** | **服务本地跑**、中间件在虚拟机 | **`192.168.150.1`**（本机 VMware 虚拟网卡） |

`bootstrap.yml` 里写死 `spring.profiles.active: dev` ⇒ 本地跑服务时注册了**虚拟机 IP**
⇒ 网关按 Nacos 里的地址转发 ⇒ 打到虚拟机上 ⇒ **连不上** ⇒ 前端 `Network Error`。

**修法：启动加 `--spring.profiles.active=local`** ✅ 改完后网关日志：
```
加载auth服务地址成功，http://192.168.150.1:8081/jwks
加载jwk秘钥成功！                    ← ★ 通了
```
`ipconfig` 确认本机确实有 **192.168.150.1**（另有 192.168.102.15 / 192.168.130.1）。
